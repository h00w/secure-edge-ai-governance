# Outreach guide

When sharing this project, lead with a reproducible technical question rather than a request for stars.

## Suggested framing

**Question:** How should an AI-assisted release workflow prove that a model or firmware artifact is actually authorized for deployment to an edge fleet?

This playground provides a runnable answer using deterministic fail-closed gates, two-person approval, risk/drift thresholds, signature and attestation evidence, regression qualification, and explicit manual hold.

## Good audiences

- Edge AI and embedded AI engineers;
- AI security and AI governance practitioners;
- MLOps / DevSecOps teams;
- trusted-computing and attestation researchers;
- agentic AI platform engineers;
- industrial IoT and OTA-security teams.

## Useful call to action

Ask reviewers to run the live demo, break one control, inspect the corresponding policy/test, and open an issue if the behavior or threat model can be improved.

Stars are welcome when the repository is genuinely useful, but technical feedback and reproducible contributions are more valuable.

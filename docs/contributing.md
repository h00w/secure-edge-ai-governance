# Contributing

Contributions that improve reproducibility, security, policy enforcement, evidence quality, documentation, or test coverage are welcome.

## Workflow

1. Open or reference a focused issue when the change is non-trivial.
2. Keep pull requests small enough to review independently.
3. Add or update tests when behavior changes.
4. Document security assumptions and operational impact.
5. Avoid committing secrets, personal data, or customer-sensitive material.

Changes to release authority, attestation, approvals, or rollback logic should include explicit rationale and regression evidence.
